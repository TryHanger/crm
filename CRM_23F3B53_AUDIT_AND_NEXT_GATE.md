## P1 — завершить публичную запись до пилота

### P1-01. Time-first не завершён, тест проверяет только вкладки
- `apps/booking-web/src/App.tsx`: `time-first` начинает со `step='datetime'`, но эффект `searchAvailability` прекращается при `selectedServices.length===0`. Клиент не видит доступных слотов, не может честно завершить сценарий «время → услуги → мастер → подтверждение».
- `tests/e2e/booking.spec.ts`, тест `Three Entry Flows`: только `toContainText()` после клика вкладок, без создания визита.
- Реализовать полноценный UX. Рекомендация: дата и предварительное **предпочтительное** время без обещания окончательной доступности; выбор услуг, подходящего мастера, повторная серверная проверка фактического интервала с длительностью и актуальной ценой, подтверждение реального слота, только затем создание записи. Если выбранное время недоступно — предложить альтернативы. В UI чётко различать предпочтение и подтверждённый слот. Сохранять контекст при Back.

**Acceptance:** отдельный E2E создаёт бронь, начав «По времени», с выбором времени, услуг и мастера. Отдельно E2E для «По мастеру» со специфической ценой/длительностью.

### P1-02. Quote обязателен для публичной записи
- `apps/api/app/modules/schemas.py`: `CreatePublicBookingRequest.quote_id` и `expected_price_minor` сейчас optional.
- `BookingEngine.create_booking`: строгая привязка срабатывает лишь если `quote_id` присутствует.
- Утвердить и реализовать контракт: публичная запись должна подтверждаться действующим привязанным quote, либо эквивалентным серверным механизмом с явным подтверждением актуальной цены; ручная CRM запись может использовать отдельный путь. Проверить отсутствие обхода price acknowledgement при прямом API-вызове.
- Стресс-тест expired/used/mismatched quote, изменение услуги/мастера, конкурентное бронирование.

### P1-03. Слоты «Любой мастер» дублируются, цены неожиданно меняются
- Текущий `DateTimeStep.tsx` отображает каждую `SlotResponse` как отдельную кнопку, включая несколько мастеров в одно и то же время. На скриншоте слоты `11:15`, `11:30`, `14:45` и другие повторяются.
- Сгруппировать по локальному времени и дате, для режима «любой мастер» детерминированно выбирать подходящий quote или показывать конкретные альтернативы (например, «от X ₸»). При выборе явно показывать назначенного мастера и окончательную стоимость; не оставлять «Любой свободный» рядом с неожиданно выросшей итоговой ценой.
- Сохранить server-authoritative availability и revalidation, не переносить расчёт в frontend.

### P1-04. Некорректные сообщения и номера визитов

### P1-05. Полное управление по ссылке
