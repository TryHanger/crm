## Закрытые дыры

1. `PUT /staff/{id}/services` принимал услугу и филиал **другой компании**, а также несуществующего мастера. Одиночный FK проверяется без RLS, поэтому такая строка сохранялась.
2. Цена мастера сохранялась для филиала, где мастер не работает: «висячая» цена, которая нигде не применяется.
3. Отрицательные цены и нулевая длительность принимались. Цена больше 2 147 483 647 вызывала 500 (переполнение `integer`).
4. Категорию другой компании можно было указать при создании и изменении услуги.
5. `/public/services?branch_id=` игнорировал филиал: клиент видел услуги, которых в его филиале нет. Чужой `branch_id` не отклонялся.
6. `PATCH /staff` с `branch_ids`, где уже был назначенный филиал, падал с 500: INSERT выполнялся раньше DELETE.
7. Цена в публичном API форматировалась через `/100` и `,.0f`: тиыны терялись при показе.

## Изменения поведения

- Новые коды ошибок 422: `CATEGORY_NOT_FOUND`, `BRANCH_NOT_FOUND`, `SERVICE_NOT_FOUND`, `STAFF_NOT_IN_BRANCH`, `DUPLICATE_OFFER`, `CURRENCY_MISMATCH`. Неизвестный мастер в `PUT /staff/{id}/services` даёт 404.
- **Для D1:** форма «Индивидуальные цены» в CRM отправляет `modalBranchId || branches[0]`. Если мастер не работает в этом филиале, сервер теперь отвечает `STAFF_NOT_IN_BRANCH`. Форме стоит выбирать филиал из филиалов мастера.
- `test_crm_api`: перед ценой во втором филиале мастера теперь назначают в этот филиал.
