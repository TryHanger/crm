## API

- `GET /business/expense-categories?include_archived` · `POST /business/expense-categories` `{name}` · `POST /business/expense-categories/{id}/archive` (только owner).
- `POST /business/expenses` `{branch_id, cash_account_id, category_id, amount_minor, reason}` + `Idempotency-Key`.
- `GET /business/expenses?branch_id&from_date&to_date` — список расходов филиала со статьёй, кассой, причиной и автором.
- `GET /business/reports/finance?from_date&to_date&branch_id?` → `{total, branches[]}`. Период не больше 366 дней, `to_date ≥ from_date`.

Ошибки: `SHIFT_REQUIRED`, `INSUFFICIENT_CASH`, `EXPENSE_CATEGORY_NOT_FOUND|ARCHIVED|EXISTS`, `IDEMPOTENCY_KEY_REQUIRED|REUSED`, `PERIOD_INVALID|TOO_LONG`.

## Приёмка M14

Визит 8000, оплата 3000. Будущая неоказанная запись в отчёт не попадает. Отчёт: **оказано 8000, получено 3000, долг 5000**. Расходы «Аренда» 1500 и «Материалы» 200: расходы 1700, денежный поток 1300, выручка не изменилась, ожидаемая сумма смены уменьшилась на 1700.

Два филиала: аванс и расходы во втором филиале, оплата в первом. Итог по каждому показателю равен сумме филиалов и совпадает с прямой суммой по журналу. Админ второго филиала видит только его.

## Для D1 (UI)

- Экран отчётов (`ReportsModule.tsx`) работает на прежних полях. `completed_revenue_minor` теперь значит «оказано по журналу», `paid_revenue_minor` — реально полученные деньги. Можно показать `debt_minor` и `expenses_minor`, а подробный разрез взять из `/reports/finance`.
- Форма расхода: статья из `/expense-categories`, касса из `/cash-accounts`. Для наличной кассы нужна открытая смена.

## Для PO

- Расход проводится датой проведения. Задним числом (например, «аренда за прошлый месяц») расходы не проводятся: закрытые периоды неизменяемы. Если такое нужно, нужна отдельная политика.
- Остаток авансов по филиалам считается по месту приёма и зачёта. В разрезе филиала он может быть отрицательным (принят в одном филиале, зачтён в другом), по компании сходится.
