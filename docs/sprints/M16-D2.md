## Gate выпуска MVP

| Гейт | Статус | Что нужно |
|---|---|---|
| Код MVP D2 (M01–M16): касса, отчёты, письма, права, RLS | **GO** | — |
| Восстановление бэкапа | **GO на стенде** | Повторить `--drill` на боевом бакете в первый день пилота и приложить отчёт |
| DNS | **NO-GO** | Купить или выделить домен, создать записи по RUNBOOK §1 |
| TLS | **NO-GO** | Выпустить сертификаты: основной (HTTP-01) и wildcard (DNS-01) по RUNBOOK §2 |
| Боевой сервер | **NO-GO** | Хост с ЦОД в РК (локализация ПД, чек-лист 1.4) |
| Offsite-хранилище | **NO-GO** | S3-совместимый бакет в другом ЦОД, ключ только к своему префиксу, lifecycle 35 дней / 12 месяцев |
| Реальная доставка писем | **NO-GO** | SMTP-провайдер, SPF/DKIM/DMARC домена отправителя; на стенде доставка доказана (M15) |
| Правовая готовность | **NO-GO** | Пункты 1.2, 1.3, 1.4, 2.1, 2.2, 4.2 чек-листа |

**Итог:** выпуск коммерческого MVP — **NO-GO** до закрытия внешних гейтов. Блокеров в коде D2 нет. Технический пилот на тестовых данных возможен сразу после появления сервера, домена и сертификатов.

## Для D1

- **Интеграция с `origin/main` (найдено перед выпуском, P0).** Фронтенд M12–M14 в `main` (`packages/api-client`) вызывает другие пути: `POST /business/payments`, `/business/payments/{id}/refund`, `/business/cash/shifts/current|open|{id}/close`, `DELETE /business/expenses/{id}`, `/business/reports/visits|services|debts`. Бэкенд D2 даёт `POST /business/bookings/{id}/payments`, `/bookings/{id}/refunds`, `/cash-shifts/open|{id}/close`, `GET /cash-shifts/{id}`, `/expenses` (без удаления: ошибочный расход — сторно `/ledger-entries/{id}/reverse`), `/reports/finance`, `/reports/overview`. При ошибке API клиент молча пишет оплаты, смены и расходы в `localStorage` (`FinanceMockStorage`): в продакшене касса показала бы деньги, которых нет в журнале. До выпуска заглушку нужно убрать и привести пути к одному контракту. `FinanceCoreService` в `main` считает «оказано» по статусу брони; в D2 это заменено журналом (M11–M14).
