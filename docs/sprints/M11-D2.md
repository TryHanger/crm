# M11 · D2 · Финансовый заказ и факт оказания: release note

Ветка: `d2/m11-orders-accrual` (от `d2/m10-customers`).

## Что сделано

| Задача | Результат |
|---|---|
| M11-D2-01 orders/items с неизменяемым снимком цены | `modules/finance/accrual.py`: заказ визита создаётся из снимка брони (`booking_items`), один на визит (`INSERT … ON CONFLICT` по `uq_order_per_booking`). Позиции заказа неизменяемы (триггер из M05), `total = unit × qty − discount` проверяется CHECK. Источник цены — `booking` («цена, по которой клиент записался», ревизия `007`), а не догадка по текущему прайсу. |
| M11-D2-02 VisitCompleted → начисление без дублей | Переход в `completed` (одна машина состояний из M09) в той же транзакции создаёт заказ и проводит `service_rendered` с ключом `visit-completed:{booking_id}`. Повтор события, параллельное завершение и backfill не создают второго начисления. Неявка и отмена ничего не начисляют. Карточка записи отдаёт блок `finance`: продано, оказано, получено, зачтённый аванс, долг — только из заказа и журнала. Мастеру блок не отдаётся. |
| M11-D2-03 миграционная карта и тесты | `scripts/backfill_orders.py` (есть `--dry-run`): заказы и начисления для визитов, завершённых до журнала, идемпотентно. Денег салона до M11 не было (отчёты показывали «оплачено = 0»), `PaymentRecord` — оплата подписки платформы, не трогается. `test_accrual.py` (6), `smoke_accrual.py` в `dev_stack --smoke` и CI. |

## Найдено по ходу

- Первая версия вычисляла `price_source` (`base` / `staff_override`), сравнивая снимок с **текущим** прайсом. Если цена услуги менялась после записи, позиция получала ложный источник. Исправлено: источник `booking`, ревизия `007` расширяет CHECK.

## Приёмка M11

- Стрижка 8 000 ₸: до завершения заказа нет. После `completed`: оказано 8 000, оплачено 0, долг 8 000, в журнале одна запись `service_rendered`.
- Цена услуги выросла до 9 900 после записи: заказ всё равно 8 000 (снимок брони).
- 6 одновременных «завершить» дают один переход, одно начисление и один заказ. Ещё три прямых вызова начисления ничего не добавляют.
- Backfill двух прогонов подряд: один заказ, одно начисление.
