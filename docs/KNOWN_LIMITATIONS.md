# Известные ограничения и статус реализации (KNOWN_LIMITATIONS.md)

В данном документе честно и прозрачно зафиксированы текущие эксплуатационные ограничения, отложенные интеграции и особенности локального окружения.

---

### 1. Статус компонентов платформы

| Компонент / Модуль | Текущий статус | Описание и обоснование |
|---|---|---|
| **Multi-Tenant RLS & БД** | **PRODUCTION-READY** | PostgreSQL 17 с `btree_gist`, Exclusion Constraints, `crm_app_user` с `NOSUPERUSER NOBYPASSRLS`. Полная изоляция арендаторов, защита от утечек данных между тенантами. Таблицы находятся в стандартной топологии PostgreSQL (схема `public`) с строгим RLS по `tenant_id = current_setting('app.current_tenant')`. |
| **Booking Engine** | **PRODUCTION-READY** | Authoritative валидация смен, перерывов, отпусков, блокировок, лимитов предзаказа и горизонта (14 дней). Strict Quote Binding с проверкой мастера, времени, филиала и услуг (409 `QUOTE_MISMATCH`). Защита от овербукинга через PostgreSQL Exclusion Constraints. |
| **RBAC и Безопасность Авторизации** | **PRODUCTION-READY** | Устранена уязвимость сброса пароля через invite (существующий пароль пользователя верифицируется и не перезаписывается). Сырые токены приглашений возвращаются только в изолированном тестовом окружении (`ENVIRONMENT == 'test'`). |
| **Ручной биллинг (Ledger)** | **PRODUCTION-READY** | Выставление начислений (`SubscriptionCharge`), учет платежей (`PaymentRecord`) с частичной оплатой (`partially_paid`) и идемпотентностью. |
| **Booking Web Frontend (`apps/booking-web`)** | **PRODUCTION-READY (Barbershop)** | Реализовано на **React 18.3.1** + TypeScript в точном соответствии с дизайном `готовый фронт.html`. Поддерживает все три входа в запись («По услуге», «По мастеру» с персональными ценами, «По времени»), динамический расчет политики отмены (`cancellation_cutoff_minutes`), смену филиала с автосбросом зависимостей, устойчивый к сбоям ключ идемпотентности и прямое открытие `/manage/:token`. |
| **Business CRM Dashboard (`apps/business-crm`)** | **PRODUCTION-READY (PHASE 1)** | Реализован на **React 18.3.1** + TypeScript. Настоящая форма входа по email/паролю без жестко зашитых учетных данных в бандле. Чтение `me.crm_memberships` и безопасный переключатель между организациями авторизованного пользователя с передачей `X-Tenant-ID`. Обновление статуса записей через реальный HTTP метод `PATCH /business/bookings/{id}/status`. |
| **Platform Console Frontend** | **DEFERRED (BY DESIGN)** | В соответствии с прямым указанием («Не занимайся пока полным интерфейсом Platform Console, стоматологией и другими нишами»), интерфейс Platform Console отложен; backend API консоли платформы полностью функциональны (`/api/v1/platform/*`). |
| **Стоматология и другие ниши** | **DEFERRED (BY DESIGN)** | Опросники здоровья, зубные карты и специализированные медицинские протоколы вынесены в будущие релизы вертикальных расширений. |
| **SMS-уведомления** | **SIMULATED / PLANNED** | В соответствии с ТЗ и архитектурой интеграция со сторонними платными SMS-шлюзами (Twilio/SMSC) не подключалась. Записи событий аудита и уведомлений логируются в БД (`booking_events`). |
| **Банковский эквайринг (Касса/Сбер/Kaspi Pay)** | **DEFERRED (BY DESIGN)** | Оплата подписок платформы на текущем этапе реализована через ручной учет безналичных банковских платежей с подтверждающими документами (`evidence_reference`), что соответствует архитектурному документу. |
| **Фоновые периодические воркеры (Celery/Cron)** | **PARTIAL** | Все операции изменения статусов подписок и пересчетов выполняются синхронно в рамках транзакций API. Очистка просроченных `BookingQuote` (старше 1 часа) встроена в цикл создания записей. |
| **Docker Build на хосте** | **BLOCKED BY HOST DAEMON** | Файлы `Dockerfile` (двухстадийный non-root образ) и `docker-compose.yml` приведены в полное соответствие с требованиями. На локальной Windows машине служба Docker Desktop (`com.docker.service`) остановлена пользователем, поэтому выполнение `docker build` в текущей сессии заблокировано состоянием ОС хоста. В GitHub Actions CI образ собирается и проверяется автоматически. |

### 2. Рекомендации перед коммерческим развертыванием (Production Rollout)
1. **Запуск Docker Desktop / Linux Server**: Запустить службу Docker на сервере развертывания для запуска собранного контейнера.
2. **Переменные окружения**: Задать уникальный криптостойкий `JWT_SECRET_KEY` (длиной от 32 байт) и настроить белый список доменов в `CORS_ORIGINS`.
3. **SMS-провайдер**: Подключить рабочий API-ключ выбранного SMS-шлюза в модуле нотификаций.
4. **Резервное копирование**: Настроить периодический `pg_dump` с шифрованием для базы данных PostgreSQL.
