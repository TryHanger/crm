# Инструкция оператора платформы (M16)

Для сотрудника платформы, который работает в Platform Console (`https://console.<ROOT_DOMAIN>`, вход только из офисной сети `PLATFORM_IP_ALLOWLIST`). Технические операции — в [deploy/production/RUNBOOK.md](../../deploy/production/RUNBOOK.md).

## Подключить новый салон

1. **Компании → Создать.** Укажите slug (адрес сайта записи `<slug>.<BOOKING_ROOT>`; латиница, цифры и дефис, менять потом нельзя), название, имя и email владельца, тариф. API: `POST /platform/tenants`.
2. Приглашение владельцу уходит письмом. Если SMTP не настроен, консоль показывает ссылку: передайте её владельцу лично или в мессенджере. Не пересылайте ссылку третьим лицам: она даёт доступ владельца. Ссылка одноразовая и действует 48 часов. Повторная отправка: **Отправить приглашение снова** (`POST /platform/tenants/{id}/resend-invite`).
3. Владелец сам создаёт филиал, мастеров, услуги, расписание и публикует сайт записи. Публикацию за владельца не включайте.
4. Проверьте сайт записи `https://<slug>.<BOOKING_ROOT>`: видны услуги и свободное время.

## Тарифы и оплата подписки

- Сменить тариф: **Компания → Тариф** (`change-plan`). Лимиты (филиалы, мастера) действуют сразу.
- Выставить счёт и отметить оплату: **Подписки → Начисления → Отметить оплату** (`record-payment`). Это оплата платформе, касса салона здесь не участвует.
- Индивидуальные лимиты (`entitlements`) — только по решению руководителя, с комментарием.

## Приостановка и возврат

- **Приостановить** (`suspend`): сайт записи перестаёт принимать записи, CRM — только чтение. Данные не удаляются. Причину укажите обязательно.
- **Возобновить** (`reactivate`) — после оплаты или решения вопроса.

## Поддержка и доступ к данным салона

- Обращения ведутся в **Поддержке** (тикеты).
- Посмотреть данные салона можно **только по согласию владельца**: запрос доступа (`access-requests`) → владелец одобряет в своей CRM → доступ на ограниченное время. Без одобрения данные салона недоступны технически. Закончили работу — **Отозвать доступ**.
- Никогда не просите у владельца пароль. Пароли сотрудникам салона владелец меняет сам.

## Обращения клиентов салонов

- «Приходят письма, не хочу» — в каждом письме есть ссылка «Отписаться». Если клиент не может ею воспользоваться, передайте обращение владельцу салона: клиенты принадлежат салону.
- «Удалите мои данные» — передайте владельцу салона и зафиксируйте обращение в тикете. Процедура и сроки — по [чек-листу](../legal/LEGAL_CHECKLIST.md) (п. 1.7).
- Вопросы оплаты услуг — к салону: платформа деньги клиентов не принимает.

## Ежедневно (5 минут)

1. Сводка мониторинга (`monitor_check.py`, алерты дежурного): всё `OK`, бэкап моложе суток.
2. **Письма**: в журнале доставок нет массовых `failed`. Если они есть, сообщите дежурному инженеру.
3. Новые тикеты разобраны.

## Чего оператор не делает

- Не меняет данные салона напрямую в базе и не правит финансовые записи: в журнале денег правки только сторно и возвратами из CRM салона.
- Не выгружает базы клиентов салонов и не передаёт их третьим лицам.
- Не включает демо-данные в production. Production такой запуск отклонит.
