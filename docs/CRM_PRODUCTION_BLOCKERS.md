# Чеклист блокеров промышленного развёртывания (CRM_PRODUCTION_BLOCKERS.md)

> Официальный реестр блокеров и обязательных проверок перед переводом платформы из стадии PILOT-CANDIDATE в PRODUCTION.
> Актуализирован по итогам закрытия финального UI и Data гейта Business CRM V1 (`fix/crm-v1-final-ui-and-data-gate`).

---

## 0. Закрытые блокеры и технические гейты (ЗАКРЫТО В fix/crm-v1-final-ui-and-data-gate)

1. **[ЗАКРЫТО] P0-UX: Рестайлинг отчетов и настроек под оригинальный макет `готовый фронт.html`**:
   - `ReportsModule.tsx`: полностью переработан в легком стиле с белыми карточками, чистыми инлайн-стилями, индикаторами выработки мастеров и дисклеймером семантики выручки. Полная адаптивность без горизонтального скролла на 320px, 390px, 1280px, 1440px.
   - `SettingsModule.tsx`: приведен к аккуратному чистому стилю макета. Унифицированные вкладки («Филиалы», «Пользователи и роли», «Компания и тариф Pro»), чистые модальные окна редактирования филиала и генерации ссылки активации сотрудника.
2. **[ЗАКРЫТО] P1: Реальный недельный календарь вместо симуляции одной даты**:
   - `CalendarModule.tsx`: режим «Неделя» рассчитывает точный диапазон недели (Пн–Вс), запрашивает бэкенд параллельно по всем 7 дням, распределяет визиты по колонкам дней в соответствии с часовым поясом филиала.
   - Реализована навигация по неделям («← Предыдущая неделя» / «Следующая неделя →») и переход в модальное окно просмотра/управления визитом по клику.
3. **[ЗАКРЫТО] P1: Изоляция прайс-листов и графиков смен мастеров по филиалам**:
   - `StaffModule.tsx`: открытие профиля мастера и переключение филиала в выпадающем списке динамически перезапрашивают график смен (`/staff/{id}/schedule?branch_id=...`) и фильтруют персональные цены строго по выбранному `branch_id`.
   - Backend `PUT /staff/{id}/services` поддерживает как плоский массив, так и обертку `{"offers": [...]}`, сохраняя уникальные персональные цены отдельно для каждого филиала.
4. **[ЗАКРЫТО] P1: Корректная семантика выручки в отчетах**:
   - В API и UI введено строгое разделение: `completed_revenue_minor` (стоимость фактически оказанных услуг) и `paid_revenue_minor = 0` (кассовые платежи, отключены в базовом MVP до подключения фискального модуля).
   - В интерфейсе `ReportsModule` выведен четкий дисклеймер о природе выручки и флаге `payment_collection_enabled: false`.
5. **[ЗАКРЫТО] P1: Устранение жестко зашитых смещений времени и строгая валидация таймзон**:
   - Удалены все жесткие сдвиги `+ 5` часов и привязка к фиксированной зоне `Asia/Almaty`.
   - Координаты карточек в сетке календаря рассчитываются динамически через `Intl.DateTimeFormat` по реальному `timezone_iana` выбранного филиала.
   - Функция `localToUtcIso` больше не выполняет скрытый сброс в UTC `:00Z` при ошибках таймзоны, а выбрасывает явное исключение.
6. **[ЗАКРЫТО] P1: Валидация считываемости и генерации QR-кодов**:
   - Генерация валидного Data-URI (`data:image/png;base64,...`) библиотекой `qrcode` с корректной ссылкой на публичный виджет онлайн-записи и кнопкой мгновенного скачивания файла.

## 1. Блокеры безопасности и аутентификации перед Production (P0)

1. **Ротация JWT секретов и хранилище ключей (KMS / Vault)**:
   - В DEV/PILOT используется переменная `JWT_SECRET_KEY`.
   - Для Production: перенос секретов в AWS Secrets Manager / HashiCorp Vault с автоматической периодической ротацией и поддержкой нескольких валидных ключей в период ротации (Key Rotation Window).
2. **Внешний транспорт одноразовых ссылок и кодов (SMS/SMTP)**:
   - Приглашения сотрудников и клиентские подтверждения требуют интеграции с промышленным провайдером транзакционных сообщений (SMSC/Twilio/Postmark) со строгим контролем лимитов отправок (Anti-Spam Throttling).
3. **CORS и Origin Protection**:
   - Строгая привязка `CORS_ORIGINS` к боевым доменам компаний и Platform Console; запрет wildcard `*`.

## 2. Инфраструктурные блокеры (P1)

1. **Production Docker Build & Registry**:
   - Пайплайн CI протестировал приложение в среде Node 20 / Python 3.11.
   - Для развертывания в кластере (Kubernetes / ECS / Nomad): сборка двухстадийного non-root Docker-образа с урезанием прав (`USER 10001:10001`) и публикация в защищенный Container Registry.
2. **PostgreSQL Backup & Disaster Recovery (DR)**:
   - Настройка непрерывного архивирования WAL (pgBackRest / WAL-G) в объектное хранилище S3 с регулярными учениями по восстановлению на контрольную точку времени (Point-in-Time Recovery, PITR).
3. **Фоновая очистка котировок (Quote Garbage Collection)**:
   - Перевод очистки просроченных `booking_quotes` на регулярный фоновый воркер (pg_cron или Celery/Redis) для снижения нагрузки на основной цикл транзакций Booking Engine.
